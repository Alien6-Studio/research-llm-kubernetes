# Validity and interpretation boundary

## Established within the qualified emulator apparatus

The 72-trial primary matrix, 12 provider-only controls, 12 quota controls and
48 fresh paired CPU trials reproduce from archived observations. Their separate
qualification blocks pass. The source, workload, image, pod membership, restart,
resource, planned-arrival deadline and provider-ledger checks define this scope.
Replicas improve useful outcomes with dependency headroom. Manipulating the
shared quota changes that relationship. The tested global policy has correct
atomic accounting but worse timely client outcomes in saturated conditions.

This is an exploratory mechanism study: three paired trace repetitions per
condition, 10-second arrival cohorts plus bounded drain, one-node kind, limited
workloads and finite offered load. Descriptive df2 Student intervals assume
normality/independence that three repetitions cannot establish. They are not
multiplicity-adjusted confirmatory tests, steady-state production capacity or
an equivalence result. Individual requests are not independent replications.

## Exclusions and alternative explanations

| Evidence | Interpretation |
| --- | --- |
| Original 21-trial pilot, both local legacy calibration blocks, local V2 4/8 CPU calibration | Whole blocks excluded; a passing subset never repairs qualification |
| GitHub primary environment versus independent LXD CPU environment | Analyze separately. Different source, hardware, scheduling and collection conditions prevent pooling |
| Paired 4/8 CPU controls on the 8-vCPU VM | Small observed differences weaken a CPU-only explanation here; uncertainty does not prove CPU irrelevance or hardware equivalence |
| Provider-only and 20k/40k/80k quota controls | Changing the suspected constraint moves outcomes here; not a universal exclusion of network, queue or CPU constraints |
| Sampled cgroup/VM/host observations | Retain missing values, steal and pressure. Sampling does not prove isolation or absence of short interference |
| Measured global lease policy | Four held active slots/worker, bounded 32-place queue, no deadline-feasibility scheduler. Negative results concern this policy, not every coordinated admission algorithm |

A useful task is HTTP 200 with a checkable correct result before its planned
client deadline. Emissions, attempts, provider consumptions and eventual answers
have different denominators. Late consumed work is never refunded into the
ledger and never becomes a useful outcome. Do not add separate stage quantiles
to describe a representative request. The published single-request illustration
is a rule-selected post hoc mechanism example, not a prevalence estimate.

Emulator units are declared consumption, not actual LLM tokens. Cohort throughput
uses arrivals followed through their deadline; completion-window throughput uses
finishes in the window. Resource costs integrate observed role traces, not
cloud billing or whole-system energy. No ROI, cost saving or HA benefit is measured.

## Actual model: transfer is not demonstrated

The native pilot records 52 actual Qwen classifications (4 warmup +48 measured).
It is a closed-loop, repetitive, warm-cache load-selection pilot. Its 4.689/s
best observed rate cannot establish a Kubernetes replica effect.

The complete local 45-trial actual-model block has 15 invalid trials and is
excluded in full. A preliminary 12-trial zero-service, model-sized qualification
passed, yet actual-inference emission/resource gates failed. These observations
do not uniquely identify the Mac, VM, GPU, transport or scheduler as the cause.

Three separate remote transport blocks retain every observation. The original
metadata path, compressed metadata path and size-conditioned 8 KiB control all
fail the unchanged 100 ms p95 latency gate. Timely emissions and HTTP success
do not repair that failure. The controls establish an unqualified transport
instrument, not an inference throughput ceiling or a uniquely diagnosed cause.
No qualified actual-model comparison followed. **Transfer of the emulator
results to a real LLM is not experimentally demonstrated.**

## Unmeasured and prospective work

HPA/KEDA configurations and protocols are prepared only; there is no measured
comparison. No new autoscaling campaign is needed to publish this study's
restricted conclusions. No diminishing-return knee beyond eight replicas,
production SLO, general model capability, energy or monetary efficiency is established.

The data can motivate deadline-aware admission as an engineering requirement.
No proposed Alien6 library, alternative scheduler, or customer-system benefit
has been evaluated. Its efficacy would require a new qualified comparison.

## Instrument integrity

Captured source hashes identify the measured instruments for replay.
Current code restricts outbound destinations and legacy redirects. The archived
sources remain exact; no measured record is relabelled as using the correction.
The original cohort's full criteria remain in `archives/legacy-methods/`.
